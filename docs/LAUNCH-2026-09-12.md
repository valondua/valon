## Deployment and recovery

- Production WordPress 7.1, PHP 8.3.33.
- Installed Polylang 3.8.9, Valon Platform and UpdraftPlus 1.26.7. Updated Yoast SEO to 28.4.
- WP Pusher deploys the theme from the existing valondua/valon repository, main branch. Its pre-existing Push-to-Deploy setting remains enabled. Valon Platform is tracked separately from main, subdirectory plugins/valon-platform, with automatic deployment disabled.
- Full UpdraftPlus backup completed at 17:40 UTC: database, plugins, themes, uploads and other files, 301.5 MB. It is manually retained on the production server. All archives passed Updraft restore preparation; the final restore operation was deliberately not run on production. Local database restoration and migration were rehearsed. An offsite backup copy was not obtained.
- To roll back: use UpdraftPlus → Backup/Restore, select the 17:40 backup and restore the selected site components. This is the complete pre-launch recovery point. The dashboard migration also keeps page revision/snapshot information, but those snapshots are not a substitute for the full backup.
- The old Contact page referenced an unavailable template. Migration now explicitly selects the default template, with a regression check. Core layouts are selected by their route metadata in the new theme.
- Polylang → Settings → URL modifications was saved with “The front page URL contains the language code instead of the page name or page id” enabled. Browser-language redirection is disabled. English uses the root URL.
